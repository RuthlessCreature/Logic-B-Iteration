# H02 FAST-TRACK：结果优先工程令（2026-10-14）

## 规则优先级
这份执行令覆盖 [旧长任务](H02_LONG_TASK_EVIDENCE_PIPELINE.md) 中“全部工作包严格串行、三股彻底认证后才可开始覆盖扩量”的效率性安排，不覆盖任何不可妥协的研究及安全边界。Codex应优先阅读本文。

**目标：尽快交付有真实分母、真实历史数据、具体异常及可复现脚本的研究结果，而不是堆砌抽象层、测试数量和技术报告。**

## 1. 三层结果，必须区分

1. TIER D = 真实数据诊断，立即开始。真实候选数量、采集覆盖率、OHLC/时间戳异常、历史ST/停牌参照、官方涨跌停价缺口、PIT不可用比例；可以依据真实历史EOD数据描述数据质量，但不能把EOD信息当作09:35特征。
2. TIER S = 合成订单仿真。固定人工fixture，严格T+1、100股手数、单股全仓、冻结成本、涨停买不到、跌停/停牌卖不掉、无后续量不成交。可出测试账本，但不能说它是历史真实收益。
3. TIER E = 已认证的开发期可执行模拟。真实历史逐股限价、真实PIT、已完成分钟时钟、ST/停牌有效时间、保守成交模型、交易成本全部有可重放证据，才允许输出手续费后净值。未通过则BLOCKED，不得以历史分钟成交量推测订单必然成交，更不得编造年化收益。

**用户要快，不允许不实成果。正式净值的准入门槛丝毫不下降。**

## 2. 并行四条泳道，而非长时间只做单个安全框架

### A. 真实候选数据覆盖（最高优先级）
- 先探查本地data-lake、旧GitHub Actions artifacts、XGB历史数据以及BaoStock 2020年1月独立日线；最大化复用，减少不必要请求。
- 依次做2020-01-03三只已知样本 -> 当日全部D-1涨停候选（此前报告94，只作为待核验分母）-> 2020年1月各日候选（此前985 symbol-days只作为待核验分母）。
- 扩至全日/整月之前必须有checkpoint、每股原始字节hash（如法律允许保留）、规范化hash、来源许可和限流。推荐最多3 worker，可用数据分区离线重放优先；禁止无节制并发采集和重传公开仓库的受限行情。
- 每完成一个交易日就发布逐symbol-day机器可读诊断：expected / fetched / sha_verified / 0935_bar / minute_session_valid / independently_sourced_ST_reference / halt_reference / official_limit_verified / PIT_verified / execution_eligible / reason codes。**分子/分母必须显示，不能只写“很多”。**
- 如果没有源权限，报告准确失败接口、可用替代来源以及已能采集的其他层，继续其他泳道。

### B. 官方逐股价格与PIT（快速解除真正瓶颈）
- 立刻检查本地或CI的Tushare权限，绝不打印Token。旧Actions的BLOCKED_MISSING_TUSHARE_TOKEN不能推导出本地也一定无权限。
- 并行调查合法可访问的逐股逐日官方涨跌停价、历史ST/停牌有效时点及发布时点；必要时在一个获批的2020-01-03样本上验证。
- 不允许用简单5/10/20%公式代替真实逐股限价；不能拿日终BaoStock ST/停牌声称09:35已获知。其他合法来源要验证日期、唯一性、单位、IPO/ST例外与许可证。
- 输出给用户一页“解锁真实回测所需的数据/权限采购清单”，有接口、限制、可用范围和是否需付费；未经明确授权不得购买、绕过API权限或泄漏账号。

### C. 精简证据认证器及端到端订单状态机（无需外部数据）
- 修复当前PIT_certified_rows仍可能由上游bool充数的问题，输出 claimed 与 independently_verified 两套计数；假SHA/假PIT/假fill不能提升verified或READY。
- 不要造第二套庞大框架。复用已有LocalParquetStore、Portfolio、TradingCosts和B0执行器做最小纵向切片：原始SHA vs规范化SHA、时间源证据、检查点、拒绝原因，固定输入可离线再现。
- 合成账本至少覆盖：09:35信号且之后才发单并隔日卖出；涨停买不到不买后排；跌停/停牌锁仓并跨日处理；NaN/Inf、分钟时间语义UNKNOWN或官方限价缺失时Fail Closed。
- 一分钟有成交量最多是必要条件，不能认证自己的委托已成交。纯合成账本不计入真实研究业绩。

### D. 最短可执行开发期回放（必须独立过认证门）
- 只在TIER E全部必要条件具备后，选择**2024-09-30至2026-06-30开发期**已认证的最短连续样本，冻结B0.0.3与E0规则，立即试跑realistic/conservative两档并列出未成交比例、锁死天数、手续费、drawdown及风险尾部；标明样本和置信限制。
- 真实输入仍有缺口时输出具体BLOCKED及所缺分区/字段，不得用2020-01工程样本冒充2024-2026开发期正式策略结论，不得给伪净值。
- 进入较长开发期只能在小段输入证据复现及冻结执行状态机审计完成后进行，绝不查看或解锁保护留出集。

## 4. Codex的立即行动序列

1. 读取H02_CODEX_LONG_TASK.md、本文、旧长任务、配置及H02代码；检查git status/branch/远端HEAD/PR/CI。其他用户本地修改禁止覆盖。
2. 第一小提交：修复误导性PIT统计和样本分母，负向测试+全量pytest+新HEAD CI。
3. 立即做FAST-1/FAST-2真实历史覆盖：优先复用现有分区和artifact，合法限流查询三股及2020-01-03全日；记录真实数值/异常/时间语义。可在这一步同时建立最小原始证据快照，而不是先做大框架。
4. 同时跑独立官方权限探针并审查合法候选来源；缺权限就发清晰的BLOCKED和用户需提供什么，不得停掉离线工作。
5. 同时复用已有B0构建合成订单账本，推进FAST-4；每次提交都跑test/smoke/config/CI。
6. 数据符合许可和质量条件才按日扩至2020-01候选；任何一层失败如实标明，并继续已独立可做的部分。
7. 若能认证真实开发期输入，立即执行FAST-5并审计；否则保留BLOCKED，形成明确下一步，不做调参。

**效率纪律**：第一优先新真实数据证据与覆盖分子/分母，第二优先官方限价/PIT瓶颈，第三优先可成交回放。不要为了“先写完所有模块”推迟FAST-1/2。每个工作会话至少尝试交付一个TIER D诊断结果和一个测试/代码增量；若无外部数据权限，交付具名错误+合法替代方案。
