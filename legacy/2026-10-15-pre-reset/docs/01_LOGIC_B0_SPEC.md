# Logic B0 Specification

## 1. B0 定义

**Logic B0 = 当前 Logic A 的冻结基线。**

### 原始原则

只从前一交易日涨停体系中寻找次日仍被市场确认的核心。

核心优先级：

1. 总龙头
2. 板块核心容量
3. 最强换手前排
4. 明确补涨核心

如果：
- 核心买不到；
- 不敢买；
- 核心未被确认；
- 市场处于冰点/明显退潮；

则基线动作是 **空仓**，不得以次优后排替代。

## 2. 为什么分成 B0-H 与 B0-P

### B0-H：Human Reference

保留人工判断：
- 总龙头
- 明星相/辨识度
- 板块核心
- 空间龙
- 退潮
- 冰点
- 负反馈扩散
- 补涨核心

它是“原始策略语义”的参考真值，但不直接作为自动回测代码。

### B0-P：Programmatic Proxy

使用当时可观察特征，生成：
- market_regime
- candidate_score
- core_type
- confirmation_score
- tradability_score
- risk_gate

B0-P 的首要任务不是追求最高收益，而是尽量稳定复现 B0-H 的选择逻辑。

## 3. 候选宇宙

交易日 t 的候选股票必须来自 t-1 的涨停体系。

基础字段：

- ts_code
- t-1 是否涨停
- 连板高度 / N日M板
- 首次涨停时间
- 最后涨停时间
- 开板次数
- 涨停状态：换手板 / T字 / 一字
- 封单金额
- 最大封单
- 换手率
- 成交额
- 流通市值
- 涨停原因 / 题材标签
- 同题材涨停数量
- 同题材连板数量
- 板块最高高度
- 全市场最高板
- 炸板率
- 跌停家数
- 高位断板反馈

## 4. 核心类型代理

### 4.1 总龙头代理

候选同时满足较高：
- 市场连板高度
- 近期辨识度
- 所属主线强度
- 成交活跃度
- 次日承接/确认

不得用 t 日收盘结果定义 t 日上午的总龙头。

### 4.2 板块核心容量代理

特征重点：
- 所属强题材
- 板块内成交额领先
- 流动性足够
- 对板块指数/涨停扩散有同步性
- 多日反复活跃，而非单纯最高连板

### 4.3 最强换手前排代理

重点：
- 非长期一字不可成交
- 换手充分
- 封板时点较强
- 开板后回封质量
- 同高度竞争中更强

### 4.4 明确补涨核心代理

必须同时有：
- 明确主线；
- 龙头已建立高度/辨识度；
- 低位候选与主线关系明确；
- 同位阶竞争中显著胜出；
- 不是单纯“低位涨停所以叫补涨”。

## 5. 市场状态

初始至少定义：

- ATTACK：可进攻
- TRIAL：可试错
- NEUTRAL：观察
- RETREAT：退潮
- ICE：冰点

特征候选：
- 全市场涨停数
- 炸板率
- 跌停数
- 连板家数
- 最高板高度
- 昨日涨停次日溢价中位数
- 昨日连板次日溢价
- 高位断板 A 杀数量
- 连续跌停高辨识度数量
- 最高空间是否压缩
- 主线板块持续性

B0 初始规则：RETREAT / ICE 禁止新开仓。

## 6. 确认

“次日仍被确认”必须指定时间。

系统采用事件化确认，而不是事后统一标签。

初始观察检查点：

- 09:25 竞价结束
- 09:35
- 10:00
- 10:30
- 14:30

若分钟数据允许，最终使用事件驱动而非固定时间点。

确认特征示例：

- 开盘涨幅
- 相对同题材强弱
- 是否快速回封
- 是否主动放量承接
- 是否出现板块扩散
- 核心竞争者是否负反馈
- 是否触发涨停但无法成交
- 分时均价/开盘价承接
- 题材指数相对强度

## 7. 交易动作

B0 只允许：

- BUY_CORE
- HOLD
- SELL
- CASH

禁止：
- BUY_BACKUP 因核心买不到而买后排；
- 当日买入后卖出；
- 未经版本定义的盘中随意切换。

## 8. 退出规则

退出是 B0 中必须单独形式化的部分，不能用模糊的“感觉不对就卖”。

第一阶段将退出拆成多个独立基线测试：

- E0：次日固定时点退出
- E1：次日确认失败退出
- E2：核心地位丢失退出
- E3：跌破明确结构阈值退出
- E4：涨停持有 / 开板退出

不同退出规则不得混在同一实验中，否则无法知道利润来源。

## 9. 未完成定义

以下语义需要通过人工标注 + 数据统计继续形式化：

- “辨识度”
- “明星相”
- “主线”
- “中位”
- “绝对高位”
- “负反馈扩散”
- “空间压缩”
- “核心买不到”的成交概率

这些是 Phase 0 的主要研究对象。
