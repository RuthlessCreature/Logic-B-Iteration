## 一、五条用户唯一优先约束

1. **证券身份统一**：核心股票ID是 `exchange + 6位证券代码`，例如 `000998.SZ`、`600000.SH`。`000998` 的历史名称更换、ST、*ST、撤销ST均不改变ID；名称和ST是 `trade_date` 上的属性，不是新股票。选股宝 `.SS` 转 `.SH`，BaoStock `sz.000998` 转 `000998.SZ`。**绝不因ST改名把同一股票的历史切断、重复统计或改代码；也不得把不同交易所证券错误合并。** ST是否允许开仓与身份是两个不同问题，本基线 **不因ST标签一律删除整个证券历史**；确实有特殊交易规则时只影响当日成交可行性。
2. **事件源唯一主口径 Xuangubao / 选股宝**：涨停、跌停、炸板、昨日涨停候选、市场情绪和厂商主题依仓库现有 `XuangubaoEvidenceProvider`；事件定义遵循实际返回字段，不再将不同供应商对齐当成整体研究的前置门槛。已有实现接口 `https://flash-api.xuangubao.com.cn/api/pool/detail?pool_name=limit_up|limit_down|limit_up_broken&date=YYYY-MM-DD`、`/market_indicator/line`；额外股票1分钟接口 `https://api-ddc-wscn.xuangubao.com.cn/market/kline`（已有适配器），作为可选增强。**接口是仓库既有实现，不代表第三方公开承诺/长期保证；按现有缓存优先、失败有限重试、合规使用。**
3. **价格源 BaoStock为主**：`bs.query_history_k_data_plus`，日线用 `frequency='d'`，分钟执行基线用 `frequency='5'`、`adjustflag='3'` (不复权)。BaoStock官方只提供5/15/30/60分钟历史，**不提供1分钟历史**；需要1分钟时可使用仓库已有选股宝 `market/kline period_type=60`，但**不是强制依赖**。所有交易价格、现金账本应来源于有日期标记的真实K线，不允许从“再入涨停事件池”直接推导盈利。
4. **唯一研究/回测日期**：`2020-01-01` 到 `2026-06-30`，含首尾的交易日。2020年初交易开始前账户为空；在研究起点之外不生成交易与收益。为处理D-1候选，开始日期后第一个具备历史上下文的完整交易日才能做信号，前几天允许warm-up和空仓，不偷读2019年价格作为本期已授权市场回报。**2026-07-01..2026-09-28旧受保护留出集仍绝不能访问/解锁。**
5. **资金/佣金/锁单**：`initial_cash=10000 CNY`；券商佣金按每次**买和卖**成交额万2.5 `0.00025`，`commission=max(5,notional*0.00025)`；涨停价默认买不进、跌停价默认卖不出——若当期买入订单的模拟成交价到达/等于有效涨停价，则默认 `NO_FILL_LIMIT_UP`，若卖出订单到达/等于有效跌停价，默认 `NO_FILL_LIMIT_DOWN`。无法确认价限时不得假装“必定成交”；标识 `LIMIT_STATUS_UNKNOWN` 并输出保守/乐观界限，但不因此停止其余样本与日线报告。
   - 100股整数买入手数，现金和买入费用充足，不能借钱、负现金、碎股买入；按现金**最多可买整手**分配，不是强行支出全部10000元。
   - A股T+1，当天买入不允许卖出；隔日涨跌停或停牌不能平仓就保持原持仓、占用本金，退出要按真实可行下一时点重试。
   - **除买卖佣金，还需明确单列历史A股卖出印花税和股票过户费**，不能把这两项悄悄加到或略去“万2.5”的券商佣金。卖出印花税在2023-08-28之前通常按0.1%，当日起减半为0.05%；股票过户费在2022-04-29之前沪深A股按0.02‰双向、当日开始统一按0.01‰双向。仅在适用市场/日期使用，具体实际券商佣金是否已含某项规费需在费用明细/模式中透明标注，禁止重复计费。
   - 初始仓位为空，最大1只股票，默认目标尽可能满仓，空仓是允许的有效结果。冻结旧B0的09:35信号、核心候选排序、T+1及 E0 次日退出语义暂沿用，**仅新合同显式覆盖旧的日期、本金、费率和“ST不得切断代码身份”的设定**，不得偷偷更改其它策略以改善收益。

## 二、替换旧「无限认证」流程的实际研究架构

```Xuangubao：每天涨停池/跌停池/炸板池（含历史缓存）
              ├── 全市场情绪、昨日候选股票
              └── 稳定 ts_code 编码及日属性
BaoStock：每日不复权K线（所有候选+在持仓）
              └── 历史5m OHLCV（最终候选和持仓的需要时段）
    → 交易日合并：2020-01-01..2026-06-30
    → 按实际可用字段生成D-1候选、D 09:35信号
    → 单票且至多1次买/1次卖，10000元可买整手
    → 对每个可成交5m bar进行涨停买入/跌停卖出锁死检查
    → 真实价格模拟下单/延迟/无法成交/T+1持仓/实际费用
    → 账户日账本：现金、股票、仓位、每笔成交、费用、每日权益
    → 权益曲线、累计收益、CAGR、MDD、已实现交易胜率、周转率、空仓比例、未成交比例
    → 同口径基准B0与研究候选比较，不基于回测收益偷偷修改冻结主配置
```

**先跑一个连续、确有数据的2020年1月pilot（同时每天覆盖统计），再按年度2020→2026分片扩展直到全期。** 回测样本必须标明实际覆盖日期和证券个数，不得以“已经准备了几万个涨停事件”冒充交易日账本。任何数据缺口单独计入 `DATA_MISSING`、`NO_FILL` 或 `SUSPENDED_HOLD`，报告样本分母；不是整项停止。时间安排不是等待任务日期，执行代理应尽可能在一次Goal内自动跑完整个可访问历史期间。

## 三、09:35 和5分钟K线的保守做法

- D-1 完成的池用于D候选，**D当天收盘后生成的涨停池或跌停池不可当成D 09:35信号**。
- BaoStock五分钟K若标记为区间结束时间，则09:35这一根只在确知于09:35完全结束后用于信号；若时间标签/数据完成语义不明，**不允许同一根K线既产出信号又作为成交**，可保守以09:40或之后的下一根完整K线判断成交，并披露信号使用的是09:30–09:35区间假设。
- 仅有日K且没有5m时，允许生成 `DAILY_ONLY_DIAGNOSTIC` 可观测统计、账户持仓约束估计和低/中/高成交情景，但**不能写成已复现的9:35逐笔成交**。允许使用独立 Xuangubao 1m 增强更精细入场，先做合理性检查即可，不无限讨论。
- 判定涨停/跌停必须先处理当期合理生效的价格限制（含ST不同涨跌幅、创业板历史变更、IPO无涨跌幅例外等）；不把证券代码与ST称谓混为一谈。事件池可用作**事后校验或目标事件**，不可当成D日开盘时已经知道的锁单事实。
- 价格缺失、停牌、整日无成交：报告 no trade/carry forward，不凭空清仓；收益曲线应区分当天无法观察市值/持仓市值估计。发生分红、送股、拆股时以有依据的公司行动调整持仓或标为收益尚不可确证，不把除权价格跳空当巨额真实亏损。

## 四、拒绝跑偏：明确停止做什么

- 不再将 **Tushare Token / `stk_limit` / `stock_st` / `suspend_d`** 作为完整研究执行的前置条件；本合同的主路径就是选股宝 + BaoStock。
- 不再把投资者心理强化、行为反馈因果识别、复杂多模型、多假设校正和概率Brier作为每轮主要交付。这些既有成果可留档，**新目标先做资金收益、成交、回撤**。
- 不再用纯事件延续概率/跌停事件率声称交易收益；不要因难以证明历史“官方认证”就在完全可用的日期跳过日K/5m成交模拟。
- 不允许伪造未有的逐分钟真实报价和绝对成交；5m层面是明确假设的**历史K线保守撮合模拟**，不是实盘订单成交证明。
