# Logic-B · 一条可跟随的自主研究闭环

## 目标
历史数据在 2020-01-01—2026-06-30，先运行明确执行假设下的人民币账户，再由大模型**提出**独立版本的规则调整，固定版本后使用相同引擎和数据做按时间的比较。AI不是历史行情或成交事实的替代品，也不能用验证期选“最优阈值”后重新称为样本外。

## 唯一市场数据口径
- 涨停、跌停、炸板、主题/情绪：选股宝（已有旧客户端可在 `legacy/.../src/logic_b/providers/xuangubao.py` 阅读并移植）。
- K线：BaoStock不复权日K，5分钟K；选股宝分钟线仅为可选补充，须显式保留原始时间戳。
- 同一股票代码（含交易所）贯穿 ST、更名、除ST；ST仅为具体交易日期的状态属性。
- 容许历史数据缺口但不能默默计算完美成交。无法建立成交事实时标记 `PARTIAL` 并披露覆盖，不填造交易。

## 账本口径
- 初始1万元，单股尽可能满仓，100股为一手，佣金双边万2.5最低各5元；历史印花税和过户费分项。
- 今天使用昨日已结束的选股宝集合确定候选，09:35决策，使用今天**标签为09:45、区间已经结束**的5m K线收盘价进行最早模拟成交；这是一种明确的保守执行近似，非真实订单。
- 涨停价买不进，跌停价卖不出，锁仓跨日；当日买入不能当日卖出。
- ST若缺状态则不得把10%当作已证实涨跌停价；价格限幅不确定的订单标 `LIMIT_BAND_UNKNOWN`。
- 公司行动需要作现金分红/送转/拆分的数量与成本处理；缺少精确公司行动的跨越日账本须报告局限，不能宣称现金净值严格正确。

## 后续机器/大模型研究循环
1. 从缓存重放固定基线，保存数据快照/哈希、股票候选、交易及日净值。
2. 大模型只能阅读训练期的指标和已知失败情况，输出**结构化候选规则提案**（名称、假设、参数、明确预测、风险）。
3. 提案先校验参数和数据可获得性，再以新的独立版本在训练期回测；选用明确口径，冻结后在2025–2026开发验证期只评估。
4. 输出基线 vs 候选的账户净值、回撤、换手、拒单、空仓和最差年份；失败规则也留档。
5. 生成“follow候选清单”：日期、证券代码、信号时间、选股理由、预计仓位、风险拒单条件、是否仅研究用途。仅建议用户自行审核，不连接实盘交易账户。
6. 没有显著、稳定的实际经济优势时结论可以是 `NO_FOLLOW`。
