# Luna Goal 固定实验合同：2025训练 → 2026H1验证（2026-10-15 用户最新指令）

> **这是当前唯一主动执行的样本窗口，优先于旧Handoff/AGENTS/README里任何“2020→2026全量采集”要求。** 旧数据/报告/代码不删除、仍可回归复现，但在本轮不得作为训练特征、优化样本或主回测收益冒用。后续扩展窗口需另经用户批准。
>
> **核心目标：** 用户能在 GitHub 看见 **真实行情下载覆盖率与占用空间**、每一轮Codex/Luna的策略假设与修改历史、训练资金/回撤的多版本曲线，以及一个在最终训练选择冻结后才评估的2026上半年验证资金曲线；以心理状态识别和逻辑A为研究对象，费用和不可成交情况必须真实约束。结论可以失败，不能虚构。

## 1. 锁定数据时间窗口、样本用途、账户

| 环节 | 日期（含首尾） | 唯一用途 |
|---|---|---|
| TRAIN | **2025-01-01 到 2025-12-31** | 训练期研究、参与者心理/Regime指标构造、规则实验、交易模拟、特征/阈值拟合、版本选择 |
| VALIDATION | **2026-01-01 到 2026-06-30** | 对训练期**冻结**的候选做前向开发验证；不得用结果回头调上一版参数或反复筛选最优模型 |
| 原2020—2024 | 本轮**不参与活动训练** | 仅历史legacy/单测背景，不进入训练汇总、收益曲线或筛选规则 |
| 2026-07-01—09-28 | **既有受保护区间** | 绝对不读取、不搜索、不解锁、不用于研究 |
| 2026-07-01以后 | 本Goal不读取 | 生产在线Runtime日期域是独立话题，不因此开放历史受保护数据 |

**资金账户：** TRAIN与VALIDATION各自从 **人民币10,000元** 开始，是**两个独立可比的模拟账户**，不能把两段曲线拼接成一个连续1万元复利盈利证明；验证第一天可**只读**训练期最后已结束交易日的D-1候选与前收盘价作warm-up，但不能带入训练期持仓/现金/收益。需要披露首日warm-up实际用到的来源及09:35可得性。

**费用与规则保持：** 券商佣金买卖双边万2.5、各笔最低5元；历史印花税/过户费分项；A股T+1；100股整数买入手数，最多1股持仓目标尽可能满仓，行情缺口或不合格则CASH；涨停默认买不到，跌停默认卖不出，停牌不可交易，锁仓跨日；ST/*ST/改名不改变交易所+六位代码的证券身份；历史价限制度与除权异常需要核对，不能假造价位。

**活跃配置：** [config/goal_2025_2026.json](../config/goal_2025_2026.json)。**旧** [config/research.json](../config/research.json) 是2020起旧回归样本配置，留存是为了已有单测/早期负样本可复现，**本轮Goal严禁以它作为默认研究配置**。

## 2. 数据源和“到底存了多少”的统一验收

唯一主行情：
- Xuangubao/选股宝：每天涨停池、跌停池、炸板池、能合法取得的历史市场情绪/主题等。不得假定D日盘后池在D09:35已知。源接口与内容含义需保存请求/版本/响应字段血缘。
- BaoStock：不复权日K，5分钟K（可选选股宝分钟线增强），带 ST、停牌、前收盘交易参考价；先修2020Q1失败发现的\`10002007\`同类错误：单证券日期频次可定位、有限重试、按月分区缓存、失败分区列表，不要整项中断。
- 首次必须先做到2025某完整可得月份 + 2026某完整可得月份的**实际真实源采集和账户重放**，再向全窗口扩展，先保证失败可恢复。

**存储现在的事实：** GitHub Actions虚拟机上的\`data/\`默认随Job销毁；原始缓存既不天然存于用户本地，也不天然存GitHub，更**没有实际接通Cloudflare R2/D1**。实现可替换 \`LocalStore\` → \`R2Store\`，必要时研究元数据写D1或SQLite；没有Cloudflare凭据/用户开通前，只能离线mock/临时持久化产物，不能说已经上云。**原始供应商行情不能提交公开GitHub。**

**用户必须看到真实、可解释的空间占用：**
- 每个供应商、类型（涨停/跌停/炸板/情绪/日K/5m/实验结果）、月份、年份的对象数/记录数/交易日覆盖数。
- 物理 \`file_count\`、\`physical_bytes\`、MiB/GiB，JSON原始文件字节与Parquet压缩字节**分别实测**，注明压缩率、平均每个股票交易日字节。
- 本地磁盘字节与R2实际对象字节**分别记录**。没有R2凭据→ \`r2_status=NOT_CONNECTED\`, \`r2_actual_bytes=null\`，不拿本地大小冒充云账单或宣称已永久存储。
- \`new_downloaded_bytes\`, \`cache_reused_bytes\`, \`failed_partitions\`, \`retries\`, \`missing_trading_days\`；按月累计增长曲线 \`storage_growth.svg\` 与数据完整率 \`coverage_by_month.csv\`。
- 可合理推算全训练+验证区间的**预计容量区间**，但与“已存字节”并列、显式标为 \`ESTIMATE\`；别给没有依据的精确GB数字。
- 数据和策略输入 \`sha256\`、源/请求日期、原始行数、规范化行数、时效性标签；多次实验应复用固定同一快照，保证比较公正。
- 本期数据集若只有候选股样本，禁止按样本数字声称“全A股市场情绪/广度”；要么采真正全市场分母，要么命名\`CANDIDATE_POOL_PROXY\`。

**对应现有代码：** \`src/logic_b/goal.py\` 的 \`physical_storage_inventory\` 现已统计本地实际文件数和字节/来源-年份；是**第一版**，需要Luna扩展月份分区、记录数、Parquet压缩和实际R2 API容量查询能力，并真实采集后写入可见报告。

## 3. 迭代研究不是黑盒，必须每轮可见可追溯

**先固定V0**：当前简单“昨日涨停入池、连板优先”是机器v0，只是负面基线，**不等于完整逻辑A**。过去2020年初大亏历史另行存档，不可因本次训练样本好坏抹掉。

每轮不得只改一个名字，必须输出：

\`\`\`
iteration_id, parent_strategy_sha, candidate_strategy_sha, git_commit_sha
data_snapshot_sha, date_window, feature_asof_schema_sha
hypothesis, participant_psychology_mechanism, observable_proxies, negative_controls
actual_code_or_config_diff, expected_direction, falsification_criteria
training_trade_count, training_net_return, training_MDD, training_turnover
training_unfilled_limit_up, training_unfilled_limit_down, training_cash_days
score_by_precommitted_train_metric, decision=KEEP|REJECT|INCONCLUSIVE, reason
smoke_test, CI_URL, missing_data, model_provider, next_train_experiment
\`\`\`

**研究优先顺序：**
1. **V0_SIMPLE_STREAK**，固定最简单昨天强势股排序/现有成本撮合/数据覆盖。
2. **V1_MARKET_STATE_GATE**：全市场风险偏好、赚钱/亏钱效应、涨跌停/炸板、最近3/5日扩散、冰点/修复/攻击/退潮，坏状态可空仓。MarketState是可观察代理而非心理因果证明。
3. **V2_NEGATIVE_FEEDBACK_VETO**：高位核心断板风险、“死尸池”、昨日强势股的亏钱效应/修复趋势，是否减少尾部风险。
4. **V3_SECTOR_CORE**：主线板块持续、广度、容量核心与前排；若历史合法标签缺失则降级为\`SECTOR_UNKNOWN\`。
5. **V4_ENTRY_CONFIRMATION**：只有可证明在D 09:35可见的竞价/早盘承接才作为入场证据；不得把D收盘情绪拿来倒推。
6. **EXIT_VARIANTS** 单独研究止盈/止损/次日退出、连续跌停锁仓与风险厌恶；不能同时修改进出场然后声称某个单独指标成功。

每个假设要允许 **FAILED**；Codex可以自主追加有限的、训练期事前登记的新实验，**不应反复到训练收益变得漂亮为止**。选优指标需预先固定，默认训练净收益加回撤惩罚，并审计成交笔数/费率/极端尾部；不靠单指标排第一就假定真实优势。

**参与者心理是核心特征研究**：近期可执行赚钱效应、亏钱效应、模仿扩散、风险厌恶、拥挤、一致预期、预期落差、板块负反馈。所有“参与者心理”只能从当时可观测行为代理提出假设，不凭空知道投资者真实成本或群体意图。报告需显示指标与 MarketState的证据、简单市场动量对照、强势和弱势期间的表现，并区分预测相关性与心理因果。

训练迭代结束前**不能使用2026H1验证收益做优化或选择**。最终冻结冠军可为V0，也可无冠军（数据不可靠），记录 \`frozen_selection.json\` 和策略SHA后，再对2026H1跑**一次预注册终局评估**。如果后续反复看2026结果，诚实标“开发验证”不能称完全独立样本外。

## 5. Luna 执行步骤与必须跨越的工程障碍

**Phase 0（立刻做）**：检查研究分支最新HEAD/CI；读本文件、\`AGENTS.md\`、Handoff、\`config/goal_2025_2026.json\`、\`src/logic_b/goal.py\`，承认旧日期在归档目录和早期README中可能存在。运行现有单测与纯合成dashboard，保证边界不漂移。

**Phase 1：完成真实来源数据采集/保存**：2025与2026H1真实 XGB/BaoStock，按月增量缓存、失败隔离、断点恢复；必须记录真实文件数量/字节/覆盖及首尾日期，先不用训练模型。修复BaoStock 10002007，或换经过核验的免费历史价格补充渠道并注明源和口径。利用R2时需用户提供Bucket/Token和权限；无凭据用本地或受限Actions artifacts/caches只是临时，不能声称永久存储。不得为了节约容量丢掉每笔买卖所需分钟行情及真实市场广度分母。

**Phase 2：靠谱的账户引擎**：增量式单程回测（当前按需pipeline反复回放历史前缀效率差），公司行动、成交异常、IPO涨跌幅、费率、跌停锁仓、T+1、交易日历；确保2025/2026两个独立账户+验证首日D-1前置信息。

**Phase 3：市场心理及 Regime**：训练期观测、滞后条件、风险状态、板块和核心；引入显式不可用 \`UNKNOWN\` 与 \`NO_FOLLOW\`。进行固定V0/V1/V2...训练比较、记录失败假设与负控制；禁止把市场上涨追认成“参与者心理已被证明”。

**Phase 4：训练期实验与冠军冻结**：将有限策略版本写入不可变 \`strategy_version_sha\`；训练2025按一个事前指标选方案，并在2026验证结果完全尚未被用于选择之前写 \`frozen_selection.json\`。

**Phase 5：2026H1最终验证**：锁定版本后2026H1只能独立回测/分析，不允许基于验证表现筛选新版本；未覆盖完整交易日或没有可执行价数据则报告 \`INSUFFICIENT\`，但保留全部已有的真实训练曲线与容量信息。

**Phase 6：图表和最终通俗可读报告**：用户看到策略从V0迭代到最后、每次为什么改、2025训练和2026验证两套资金曲线、实际数据占用GiB/来源/月份、哪一段丢数据、风险与交易成本、可否人工Follow。能直接用GitHub Actions附件打开HTML，和GitHub聚合摘要互相链接。

## 6. 不可突破的工程/部署边界

- 保持 PR #1 Draft，仅研究分支，禁止修改\`main\`、合并、force push。
- \`legacy/\`不恢复运行，旧日期资料不加入本次2025训练。
- 不允许越过2026-06-30取历史市场数据；尤不可接触原2026-07-01—09-28受保护历史样本。
- 研究Codex/OpenAI可自主研发策略版本；DeepSeek/Jev是未来已发布策略的**生产运行时推理**，当前默认禁用、密钥和付费激活需单独授权，不可让它们代替Codex做“训练”。
- 数据源API响应、训练/验证集、模型评分、收益与账户执行都可失败；**但不能造数据、造图表、造真实成交，更不能把概率预测称真实赚钱能力**。
- 2026H1已经被之前研究多次看到，因此它是**开发验证期**，不是完全独立且未接触的盲测；数据窗口缩短为2025+2026H1时有效样本更少，应控制多重试验、避免选择偏差、扩大置信区间披露。
- 不为迭代而迭代，不追求利润曲线单调改善；策略即使始终\`NO_FOLLOW\`也应完整结项。
