# Iteration Protocol

## 1. 版本规则

- B0 = 冻结 Logic A 基线
- B0.x = B0 的形式化/数据修复，不代表策略思想升级
- B1, B2, ... = 经验证的新策略版本

版本升级必须有明确的差异说明。

## 2. 一次实验只解决一个主要问题

模板：

```yaml
experiment_id:
base_version:
hypothesis:
mechanism:
change:
primary_metric:
guardrail_metrics:
train_window:
validation_window:
blind_holdout_touched: false
expected_failure_mode:
promotion_gate:
result:
decision:
```

## 3. 迭代来源

新假设只能优先来自：

1. B(n) 的真实亏损案例聚类；
2. B0-H 与 B0-P 的偏差；
3. 不可成交信号；
4. 特定市场 regime 下的系统性失效；
5. 明确可解释的市场微观结构。

不优先从“扫描 500 个因子挑最赚钱的”开始。

## 4. Failure Case Taxonomy

初始分类：

- F01：买到后排，前排继续强
- F02：高位周期退潮仍开仓
- F03：核心买不到后替代交易
- F04：中位股失去风险收益比
- F05：一致加速后首次大分歧
- F06：板块只有个股，没有阵型
- F07：板块有阵型但核心识别错误
- F08：竞价确认后开盘迅速反杀
- F09：回封质量虚假
- F10：空间压缩期接力
- F11：死尸池负反馈扩散
- F12：买入信号正确但实际不可成交
- F13：卖出规则损失主要利润
- F14：过早卖出真核心
- F15：持有失去核心地位的票
- F16：题材分类错误/事后归因
- F17：数据错误或复权错误
- F18：规则变化未日期化

## 5. Promotion Gate

新版本相对基线升级时，建议至少满足：

- validation 几何收益不恶化；
- 最大回撤有改善或在允许范围；
- Profit Factor 不恶化；
- 最差季度不显著恶化；
- 交易数量不低于统计下限；
- 收益不依赖极少数异常交易；
- Fill-C 下仍具有正期望；
- 参数邻域仍有效；
- 多个 walk-forward fold 不出现明显单边失效；
- 规则复杂度增加必须换来足够的稳健提升。

任何一个关键 guardrail 失败，则不升级。

## 6. Rejected Experiments

失败实验不删除。

保存：
- 原假设
- 数据
- 参数
- 结果
- 为什么失败
- 是否可能在特定 regime 有条件成立

这可以防止未来重复踩同一个坑。

## 7. 下一阶段可研究问题

优先级建议：

### P0
1. “中位”是否存在结构性负期望？
2. 最高板断板后，空间高度压缩是否具有可量化持续性？
3. 昨日涨停次日确认中，哪些确认特征真正提高赔率？
4. 死尸池负反馈对次日高位接力胜率影响多大？
5. 核心不可成交时，“空仓”相对买后排的真实机会成本。

### P1
6. 板块涨停宽度 vs 龙头高度谁更重要？
7. 回封次数/回封时间对次日溢价的条件分布。
8. 一字板、T字板、换手板的后续收益差异。
9. 绝对高位 vs 低位补涨在不同 regime 的收益结构。
10. 固定次日卖出 vs 核心地位驱动卖出的差异。

### P2
11. 龙虎榜/席位是否增加有效信息。
12. 公告/新闻催化是否能形成可复现增量。
13. 分时形态 embedding 是否优于人工规则。
14. 小模型/LLM 是否适合作为题材语义归类器，而非直接预测涨跌。

## 8. Stop Conditions

若经过足够样本后出现以下情形，应停止复杂化：

- B0 在真实成交下本身无正期望；
- 所有改进只在开发集有效；
- 交易收益主要由无法真实成交的涨停产生；
- 规则复杂度持续上升但 holdout 无改善；
- 市场制度变化导致历史样本不可比且无法校正。

此时应重新定义策略问题，而不是继续给屎山式规则加条件。
