# Logic-B-Iteration

将现有的“逻辑A”形式化为 **Logic B0**，并基于 A 股逐日历史数据进行可复现、可审计、可滚动迭代的超短交易研究。

> 目标不是把历史收益曲线拟合得最好看，而是寻找在不同市场阶段仍具有正期望、可执行、可解释、可复现的规则。

## 核心定义

- **B0-H**：人工版 Logic A。保留“总龙头 / 板块核心容量 / 最强换手前排 / 明确补涨核心 / 冰点退潮空仓”等原始语义，作为人工审计基准。
- **B0-P**：可程序化代理版。只使用决策时点已经可见的数据，将 B0-H 的语义映射为可计算特征和规则。
- **B(n)**：在严格 walk-forward 验证下，相对前一版本通过升级门槛的新版本。
- **Experiment**：一次只验证一个主要假设，必须记录数据窗口、参数、结果、失败案例和结论。
- **Promotion**：版本升级不是“收益更高”即可，必须同时通过收益、回撤、稳定性、样本量、可执行性和复杂度门槛。

## 基线交易约束

1. 市场：A 股。
2. 交易制度：T+1。
3. 基线仓位：单票满仓；同一时点最多一个持仓。
4. 候选集：前一交易日涨停体系中的股票。
5. 核心优先级：总龙头 > 板块核心容量 > 最强换手前排 > 明确补涨核心。
6. 若核心不可买、确认不足或市场处于冰点/明显退潮：空仓。
7. 不允许用后排/杂毛替代买不到的核心。
8. 回测必须建模：涨跌停规则、ST/板块规则变化、停牌、除权复权、不可成交涨停、跌停无法卖出、手续费/印花税、滑点和排队成交不确定性。

## 研究区间

初始主研究区间：**2024-09-30 ~ 2026-09-28**。

该区间之后采用滚动追加，不把未来新数据重新混入旧版本的开发集。

## 方法

```text
历史原始数据
    ↓
Point-in-time 数据层
    ↓
每日涨停体系 / 板块结构 / 空间生态 / 负反馈
    ↓
B0-H 人工语义标签 ←→ B0-P 机器代理
    ↓
事件驱动回放（严格禁止未来函数）
    ↓
交易执行模拟（T+1 / 可买性 / 可卖性 / 成本）
    ↓
收益与风险分析
    ↓
失败样本聚类
    ↓
提出一个新假设
    ↓
B0 → B1 → B2 → ...
    ↓
Walk-forward / blind holdout
    ↓
通过升级门槛才 Promotion
```

## 不以单一收益率作为优化目标

核心目标是稳健的几何增长，而不是暴力拟合 CAGR。

建议基础目标函数：

```text
score =
    annualized_log_return
    - λ1 * max_drawdown
    - λ2 * left_tail_loss
    - λ3 * instability_across_regimes
    - λ4 * complexity_penalty
    - λ5 * unfillable_trade_penalty
```

必须同时报告：

- 总收益 / 年化收益
- 最大回撤
- Calmar
- Profit Factor
- 胜率
- 单笔收益均值 / 中位数
- 盈亏比
- 最大连续亏损
- 交易次数
- 市场暴露率
- 不可成交比例
- 次日跌停锁死比例
- 分市场阶段表现
- 月度 / 季度收益稳定性
- bootstrap 置信区间

## 防止过拟合

- 时间序列 walk-forward，不随机 shuffle。
- 开发集、验证集、最终 blind holdout 分离。
- 每次版本只允许少量规则变化。
- 所有失败实验也必须保留。
- 参数搜索必须记录完整搜索空间。
- 对参数数量施加复杂度惩罚。
- 任何规则必须解释“为什么会存在可持续的市场机制”，不能只因为历史上赚钱。
- 最终收益估算必须包含成交约束，不能把一字板、秒板默认当作可成交。
- 禁止用当日收盘后才知道的信息决定当日上午的买入。

## 初始数据建议

优先构建可替换 provider：

1. Tushare：涨停/跌停/炸板榜单、连板信息、日线、基础指标等。
2. 分钟数据源：用于精确还原确认时点、开板、回封和实际可成交价格。
3. AKShare / 东方财富数据：用于交叉验证与补充，不作为唯一不可替换依赖。

所有数据必须保存：
- source
- retrieval_time
- effective_time
- raw snapshot/hash
- schema_version
